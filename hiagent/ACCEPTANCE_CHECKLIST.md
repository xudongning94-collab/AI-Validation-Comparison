# HiAgent / 飞书端到端验收清单

## A. API 与网络

- [ ] HiAgent 能通过受控 HTTPS 地址访问 `/health`。
- [ ] 健康检查返回 `status=ok`、`api_version=1.0.0`。
- [ ] API 网关已启用鉴权、请求大小限制和访问审计。
- [ ] 2–5 份 DOCX/PDF 可上传；错误数量、格式和超限文件能安全失败。
- [ ] 超时与 5xx 重试不超过 2 次，4xx 不自动重试。

## B. 工作流

- [ ] `/v1/analyze` 单次调用返回 `findings`、`scoring`、`report` 和 `task`。
- [ ] Finding 按 `finding_id` 去重且完整保留定位信息，任务详情审计链有效。
- [ ] 聚合分析失败时落库失败状态，且不生成伪成功报告。
- [ ] DOCX 批注为可选节点，不覆盖源文件。
- [ ] 单份批注失败会显示在最终结果中，不掩盖失败。
- [ ] `/v1/signature-check` 使用版本化规则，并保留规则 ID、页码、坐标与候选 ID。
- [ ] OCR/视觉 worker 不可用时显示“证据不可用/需复核”，不显示为确定性漏签或漏章。
- [ ] 公司名称、签署人、日期和位置异常均能回溯到规则与证据来源。
- [ ] 界面明确提示系统不能鉴定签名或印章真伪。

## C. 报告质量

- [ ] 本地确定性报告通过 `schemas/report.schema.json` 校验，关闭 LLM 时仍可完整生成。
- [ ] 报告分数、风险等级、文档 ID 和 Finding ID 均来自输入。
- [ ] 报告没有虚构 Finding、定位、文件或违规结论。
- [ ] AI 疑似度明确标注为非诊断性辅助信号。
- [ ] 报告不大段复制正文，不包含内部路径或访问令牌。

## D. 飞书卡片

- [ ] 渲染后卡片仍是有效 JSON，且 `schema=2.0`。
- [ ] 低/中/高风险对应的颜色和中文标签正确。
- [ ] 缺少 `report_url` 时完整删除按钮，而不是发送空链接。
- [ ] 卡片包含人工复核与非确定性声明。
- [ ] PC 和移动端均无截断、溢出或不可点击元素。
- [ ] 发送失败时保留任务 ID 和飞书请求 ID，日志中无密钥。

## E. 真实样本回归

- [ ] 使用已脱敏或获授权的真实样本执行一次完整流程。
- [ ] 源文件运行前后 SHA-256 不变。
- [ ] API、报告、卡片和批注中的文档/ Finding ID 可相互追溯。
- [ ] 人工抽检高风险 Finding 的定位与摘要一致。
- [ ] 记录总耗时、各节点耗时和失败重试次数。

## F. 发布门禁

- [ ] 本地全量测试和 Schema 校验通过。
- [ ] HiAgent 测试工作流导出并纳入版本管理。
- [ ] Prompt、工作流和卡片模板版本均写入发布记录。
- [ ] 完成权限、保留期限和接收人范围评审。
- [ ] 指定回滚方式和责任人后再发布生产版本。
